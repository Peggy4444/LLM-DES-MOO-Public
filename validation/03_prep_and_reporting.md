# Preparation and post-session reporting

## The three raw artifacts you must have ready for the paired tasks

The before/after comparison depends on being able to show the underlying
data *without any LLM narration alongside it*. Prepare each of these as
a separate on-screen view or printed sheet so you can reveal them in the
right order.

### For T1 — DES topology

- **Raw:** the machine parameter table (one row per operation, columns:
  cycle time, availability, MTBF, MTTR, working power, idle power). Show
  as a plain table. Do **not** show the Mermaid diagram yet.
- **LLM output:** the Mermaid diagram from the visualizer agent plus any
  natural-language summary the framework attaches to it.

### For T2 — Pareto interpretation

- **Raw:** the Pareto CSV as a table + a scatter plot with only the axes
  labeled (TH on one axis, WIP on the other). No knee marker, no
  highlighted points, no colored regions, no LLM commentary.
- **LLM output:** the same scatter with the LLM's chosen knee / low-WIP
  / high-TH points highlighted, together with the LLM's paragraph of
  interpretation.

### For T3 — Bottleneck analysis

- **Raw:** the SCORE frequency table — for each machine and each
  improvement variable (availability, MTTR, PT), the frequency with which
  the variable was activated in the non-dominated solutions. Do **not**
  show the ranking or the rationale yet.
- **LLM output:** the ranked alleviation list with the natural-language
  rationale generated by the bottleneck agent.

If your Streamlit UI already shows the raw and the LLM output together,
prepare masked screenshots (raw first, LLM overlay second) so you control
the reveal.

## What to record during Block 4 (paired tasks)

For each of T1, T2, T3, write down verbatim (or note timestamps in the
recording so you can transcribe later):

- The **first sentence** the participant says when they see the raw data.
- The **single main conclusion** they draw before the LLM output is
  revealed (e.g., "the bottleneck is the washing machine because...").
- The **first reaction** they have when the LLM output appears.
- Any **disagreement** they voice, and whether they revise their own
  view after seeing the LLM.

The disagreement pattern is the key evidence: does the LLM confirm the
expert, add signal the expert missed, or lead the expert away from a
correct conclusion?

## After the session — how to score and report

### 1. Per-artifact ratings (Table X in the paper)

Compile both participants' scores into one table. Report median and
range, not mean, because N=2.

Example:

| Artifact | Correct | Clear | Trust | Action | Verify |
|---|---|---|---|---|---|
| Mermaid diagram | 4 [4–4] | 4 [3–5] | 3 [3–3] | 3 [2–4] | 4 [4–4] |
| SCORE rationale | 5 [4–5] | 4 [4–4] | 4 [3–4] | 4 [4–4] | 3 [3–3] |
| ... | ... | ... | ... | ... | ... |

### 2. Comparison-to-current-workflow scores

Report as a short paragraph or a stacked-bar figure. Emphasize any
artifact where both participants scored ≥ +1 (framework strictly
preferred) or ≤ −1 (framework strictly worse).

### 3. Before/after agreement (the headline result)

Report as a small table:

| Task | P1 agreement | P2 agreement | Notes |
|---|---|---|---|
| T1 topology | Full | Partial | P2 noted missing defect-rate annotation |
| T2 Pareto | Partial | Full | Both would have picked a slightly different knee |
| T3 bottleneck | Full | Full | Both confirmed top-ranked machine |

Then one paragraph per task with a representative verbatim quote from
each participant.

### 4. SUS and trust scores

Report both participants' scores individually. Standard SUS
interpretation bands: below 50 = poor; 50–68 = below average; 68 =
average; above 80 = excellent. Do not average N=2. Just report both.

### 5. Adoption-barrier item and interview quotes

One paragraph per theme (trust, decision value, adoption barriers). One
verbatim quote per theme per participant if possible.
